Overview

The viewer replays recorded flight tracks over a Leaflet map on a scrubable UTC timeline. It is a single-page application: one map canvas fills the window, and every panel is an overlay docked to an edge of it. There are no separate routes except the dataset-creation page.

Who uses it

ANSP operational and engineering staff — air traffic controllers, CNS engineers, airspace planners, flow management (ATFM) and the airspace management cell. The vocabulary throughout is ICAO/AIP standard: flight levels, nautical miles, knots, UTC, runway designators, AIRAC cycles. One panel set serves all roles; there are no per-role views.

Cache policy matters when rebuilding: /assets/* is immutable for a year, while HTML, .json and .geojson are served no-cache so data refreshes without a version bump. Build modes are historical, live and sim; in development they run on ports 5175, 5176 and 5177 respectively.

About the data in these screenshots

Every figure was captured against a synthetic dataset generated for this document — 25 fabricated flights over a 2 h 27 min window. Callsigns and operator codes (DEM, SMP, TST, SYN, EXA, MOC) are invented and deliberately not real ICAO airline designators. No operational surveillance data appears anywhere on this page.

Aerodrome codes and the VTBS runway thresholds are real, because they are public AIP data and the movement filters, runway panel and holding detector need true geometry to behave normally. Dataset names visible in list controls have also been replaced. Three figures — the sector timeline strip — could only come from a database dataset; they are flagged where they appear and their identifiers were rewritten before capture.

Screen anatomy

One map fills the viewport. A command bar spans the top, the timeline sits directly under it, and everything else is a corner-docked overlay. Panels open over the map rather than reflowing it, so the map never resizes while the user works.

  2. Cursor clockCurrent replay time, always UTC, to the second.
  3. TimelineScrubber across the dataset's full extent. Drag to seek.
  4. Flight countLoaded flight total; also the toggle for the flight list.
  5. SearchType-ahead over callsign and aerodrome; arrow keys and Enter to pick.

  7. Zoom clusterZoom in, out, and Reset back to the default extent.
  8. Phase legendColour key for vertical phase: climb, cruise, descend, unknown.

  10. Basemap switcherDark, Light, Street, Satellite.

Dataset loader

The application opens on a modal loader over the map. Nothing else is usable until a dataset is loaded. Five source tabs are present in the historical build; each has its own fields, and all share the filter block underneath (departure/destination, aerodrome, operator, callsign, UTC time window) so the fetch can be narrowed before it runs.

Gap worth knowing before you build

The CSV parser builds each point as a fixed tuple that has no ground-speed slot — there is no column you can add to populate FlightPoint.gs. Several behaviours gate on ground speed and therefore stay silent on CSV input. This is covered concretely under Notes for the developer.

Timeline

Targets and trails

Aircraft are drawn as heading-rotated symbols coloured by vertical phase. Trails are off by default; once enabled they decay over a chosen window so the display stays readable in dense traffic.

Flight list and target selection

Sector timeline strip

When the loaded dataset has ATC sector data, the locked-flight card gains a second ribbon beneath the altitude profile: a Gantt of which sector was controlling the flight, drawn on the same time axis as the profile and under the same playhead, so a level-off and the handoff that went with it line up vertically.

Each segment is one control period. The label is clipped to the segment's width — the fourth here reads SMT because the period is too short to fit SMTWR — and the full name plus its source is on the hover title. A period with zero measurable duration still renders, as a 2 px sliver, so a momentary handoff is never invisible. The distinct sector names seen across the loaded set are collected into sectorColorLegend.

En route (ACC) periods are capped at the recorded enroute-out handoff. Where no handoff was recorded, they are capped at the Bangkok FIR boundary — computed by walking backwards from the last track point against the FIR outline — and only then fall back to the end of the track. Approach and tower periods always run to the end of the track. Without that capping an ACC label would otherwise linger past the FIR on departures, or sit behind the arrival sectors on arrivals.

This is the one figure pair from real data

Sector periods come from a date-gated backend lookup keyed by flight key, so a synthetic track can never populate them — these two figures were captured from a database dataset. The callsign, the dataset name and the date were rewritten in the DOM before capture. Sector designators and the relative timings are genuine, because they are the thing being documented.

In the wider view below, every value taken from the filed flight plan or the airframe record is redacted — registration, RFL, off-block/T-O, landing est/act, EET, alternate, equipment and the filed route. Field labels are left in place, so the card's layout still reads. Values derived from the track itself are genuine: the aerodrome pair, first and last times, IAS, track, ROCD, geometric altitude, the controlling sector, and the profile and strip.

Symbology

CWP symbology switches targets to controller-working-position presentation. Vector draws a speed vector projecting the aircraft's position ahead by Off / 1 / 2 / 3 / 6 / 9 minutes. New ring presets the default radius for range rings added from the target menu, from 3 NM to 6 NM in half-mile steps.

Basemaps

Dark is the default and the one the target palette is tuned for; phase colours lose contrast against Street and Satellite, which is worth knowing before choosing a basemap for a screenshot or a video.

Filter panel

Docked left, 280 px wide, opened by #btn-filter. Criteria are staged and then committed with Apply, which shows the matching count — the map does not churn while the user is still composing a query. Clear resets to the unfiltered set.

Airport block — always visible

  • DEP / DEST — which end of the route the aerodrome selection applies to.
  • Quick chips — BKK TMA, VTBS, VTBD, VTCC, VTUU and a dropdown for the rest.
  • Range rings — concentric rings at 25 NM steps out to 200 NM from the chosen aerodrome.
  • Procedures — draws SID, STAR, ILS and PBN procedures for that aerodrome in one action.

Analysis panels

Two panels do not merely display the data — they derive events from track geometry. Both explain their own detection rules in an inline footnote, which is the authoritative statement of what they count.

Runway movements

  • Aerodrome selector — every VT aerodrome; the per-runway ends update to match.
  • Sequence numbers on targets — writes the arrival sequence number onto the map symbols.
  • Per-runway counters — movement totals for the whole dataset, per runway end.
  • Ladder axis — from 10 minutes before the cursor to 20 minutes after.
  • Row kinds — arrival, departure or go-around, with aircraft type and wake category.
  • Gap — time since the previous movement, and for arrivals the distance behind the previous arrival at the threshold; flagged below 3 NM or the wake minimum.
  • Compression advisory (yellow) — raised while a follower is projected to end up inside required spacing plus 0.5 NM with a minute or more to act; cleared when the projection recovers.
  • Spacing alert (orange) — an approach that got within 4 NM of its leader while more than 10 kt faster; the map ring persists to landing or go-around.

A ~ against a time means it was extrapolated from the first or last radar point at that aircraft's ground speed rather than observed directly.

Holding

A hold is a track that closes on itself: back within 0.54 NM of a point 100 s or more earlier after roughly a full turn, level within 1,500 ft. Laps at one place merge into a single entry. Circuits and go-arounds at a field — below 2,500 ft within 6 NM — are excluded. Fix names the published pattern whose racetrack centre lies within 2 NM, otherwise the hold is reported as ad hoc. Clicking a row jumps the cursor to the hold's start.

URL parameters

Deep links open the viewer preloaded, which is how the dataset-creation page hands off and how reports link to a specific flight.

PatternEffect
?dataset=<name>&autoload=1Opens the Airborne tab on that named dataset and loads it.
?tab=database&date=&callsign=&autoload=1Builds the dataset if missing, then plays that one flight.

autoload=1 is what turns a pre-filled form into an actual fetch; without it the parameters populate the loader and wait for the user.

Notes for the developer

Behaviours that are not visible in a screenshot, and that cost time to rediscover.

CSV input cannot drive the runway panel

Arrival and departure detection both gate on ground speed: the arrival test requires (p.gs ?? 0) >= 60 and the departure roll requires >= 100 (src/utils/aman/playback/movements.ts). The CSV parser builds each point as a fixed tuple with no ground-speed field, so gs is always null on this path and neither arrivals nor departures are ever detected from a CSV dataset.

The go-around detector works from flight-level climb instead, so it does fire — which is why the panel in this document reports go-arounds against a runway that, in the synthetic data, only has departures. Load a database, Recent or Aireon dataset to exercise the panel properly. Adding a ground-speed column to the CSV contract would be a small, self-contained improvement.

Sector timelines cannot come from CSV

The strip reads sectorTimelines, populated by a backend fetch of ATC control periods, not computed in the browser. That request is gated on the date derived from the loaded flights and its response is keyed by flight key, so a synthetic or renamed track matches nothing and the collection stays empty — the strip then does not render at all, even though sectorEnrouteAvailable reads true. Only a database, Recent or Aireon dataset populates it. See the strip under Replay core.

The fetch is debounced so a progressive multi-batch load issues one request rather than one per batch, and superseded requests are aborted — an earlier version saturated Chrome's six-connection-per-origin limit and starved every other request to the backend. Live mode never fetches at all; the overlay is a historical-playback feature.

Record needs a secure context and a real click

The Record button uses getDisplayMedia, which requires both a secure context and a genuine user gesture. It cannot be driven headlessly and does nothing over plain HTTP on a non-localhost origin. Offline video is produced by a separate Playwright pipeline that drives setCurrentTime frame by frame and pipes screenshots to ffmpeg, rather than through this button.

Locking a flight reveals the future

Locking a target draws its complete route, coloured by phase — including the portion after the cursor. For a replay intended to show only what had happened by a given moment, those polylines have to be removed after locking; they are not recreated on time change. Locking also attaches a follow camera that calls panTo on every time step.

Data-driven vs compiled in

Aeronautical content — airspace volumes, procedures, airways, CNS coverage — is fetched from the hubs behind /aixm-hub and /cns-hub and carries its own AIRAC cycle, shown in each panel footer. Note the two cycles are independent: airspace was on 2609 while procedures were on 2602 at capture time, so do not assume one cycle across the app.

Aerodrome and runway reference data are static files under public/airports/. Trail line weight is a compile-time constant, not a user setting.

Reproducing these captures

The figures were produced by driving the running application with Playwright against the synthetic dataset, at a fixed 1440 × 900 viewport and device scale factor 2. The store setters and window.mapInstance were used to reach each state deterministically rather than clicking through the UI, and cursor times were derived from the dataset itself so that each panel was captured at a moment where it had something to show.
